## Phase 1B — R58 Fork API + dashboard 按鈕

**Priority**: P1
**When**: phase 1A 上線 dogfood 1 週後動
**What**:
- `POST /api/projects/:id/fork` endpoint
- Body: `{ name, customDomain, copyEnvVars?: false, copyAutoGeneratedSecrets?: false }`
- 行為：複製 source 的 `gcsFixedSourceUri` → 新 project row（status=submitted）→ 走 standard pipeline
- Dashboard: 每個 project 詳細頁加 `[Fork this app]` 按鈕（modal）

**Why**:
- User dogfood 完想拿部署好的 code 改後重 deploy → 現在路徑是「source-download → 解壓 → 改 → 重新 submit-gcs」太多步
- 「為什麼不是 GitHub Actions」差異化的核心 — 一鍵 fork 是 platform 才有的

**Where to start**: `apps/api/src/routes/projects.ts` 新 endpoint；參考既有 `submit-gcs` flow

**Depends on**: phase 1A 穩定（migration step 不破 fork 流程）

**Context**:
- Reviewer 提的 risks（CEO plan reviewer concerns 區）：
  - slug uniqueness race condition 要 handle（INSERT 同名兩次的 case）
  - async fork redirect UX：fork → pipeline scan/build 要 5-10 min，dashboard 要 spinner page or status page
  - copyEnvVars=true toggle 仍走 R49 deny-list 過濾（API_KEY/PASSWORD/STRIPE_*/...）
- 不複製 DB data（v1 限制）— 文件 + tooltip 講清楚
