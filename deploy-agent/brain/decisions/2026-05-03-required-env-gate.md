# 2026-05-03 — Required env-var gate（R49）

## Status

Active

## Context

兩個 Python FastAPI 專案部署掛在同一類問題：

```
# luca-optimizer-kb
File "/app/app/auth.py", line 20, in <module>
    JWT_SECRET = os.environ["LUCA_JWT_SECRET"]
KeyError: 'LUCA_JWT_SECRET'

# wavenet-ai-gateway-backend
File "/app/app/config.py", line 67, in __init__
    raise RuntimeError("erp-jwt-secret is required but not available from Secret Manager")
```

兩個都是 container 在 Cloud Run 啟動時、import app module 階段就炸（`os.environ["X"]` 直接 KeyError 或 Pydantic Settings 必填欄位沒提供）。容器啟動失敗 → 沒 listen on PORT → Cloud Run health check 4 分鐘 timeout → deploy 失敗。

**浪費**：4 分鐘等 timeout、Cloud Build 分鐘、Artifact Registry 儲存、Cloud Run quota。其實這些 missing env vars 在我們 scan 時就看得出來，沒理由讓它跑到 Cloud Run 才死。

**現有狀態**：`env-detector.ts` 已經做了 80% 的工作（掃 `process.env.X` / `os.environ["X"]`、自動產生 secret、有 LLM classifier）。Bug 在 `deploy-worker.ts:313-315`：當 `envDetection.missing.length > 0`，**只 log warning 然後繼續 deploy**。Warning 變成 4 分鐘 Cloud Run timeout。

## Decision

### Part 1：Python-specific source 掃描器

`apps/api/src/services/python-env-extractor.ts` — pure function，掃 projectDir 裡的 `*.py` 檔（skip `venv/`, `.venv/`, `__pycache__/`, files >50KB），輸出：

```typescript
interface PythonEnvRef {
  name: string;
  required: boolean;
  source: 'os.environ' | 'os.getenv' | 'pydantic-settings' | 'secret-manager';
  location?: string;  // file:line
}
```

辨識：
- `os.environ["X"]` → required（KeyError on missing）
- `os.environ.get("X")` / `os.getenv("X")` → optional，**但**若下一行非空白行是 `if not <var>: raise` / `if <var> is None: raise` / `assert <var>` → upgrade 為 required
- Pydantic `BaseSettings` 子類別：類別 body 內 `field: type` 沒 default → required；`field: type = "default"` / `field: Optional[X] = None` → optional；`Field(...)` no default → required；`Field(default=None)` → optional
- Google Secret Manager：`client.access_secret_version(name=f"...secrets/X/...")` 提取 `X` → required

**string masking**：triple-quoted docstring + 一般字串都會 mask 掉 — 避免 `doc = "use os.environ['X']"` 被誤判（call site 在字串內就 skip；`name` capture 在字串內 OK 因為那是 literal arg）。

### Part 2：Pure decider gate

`apps/api/src/services/required-env-gate.ts` — pure function，吃 refs + 已設定的 env vars + settings flag → verdict：

```typescript
type EnvGateVerdict =
  | { kind: 'ok' }
  | { kind: 'auto-generated'; generated: Record<string, string>; names: string[] }
  | { kind: 'block'; missingRequired: Array<{name, reason, hint}> };
```

**Auto-gen 白名單**（刻意窄 — 比原 plan 更窄）：
- `*JWT*SECRET*`
- `*SESSION_SECRET*`
- `NEXTAUTH_SECRET`
- `*SIGNING_KEY*`
- `*ENCRYPTION_KEY*`
- `*CSRF*SECRET*`

**Deny 列表**（paired credentials，**永不** auto-gen，一律 block）：
- `*PASSWORD*`、`*_API_KEY`、`*_ACCESS_TOKEN`、`*_CLIENT_SECRET`、`*_WEBHOOK*`
- 前綴 `STRIPE_*`、`OPENAI_*`、`ANTHROPIC_*`、`GOOGLE_*`、`AWS_*`、`SUPABASE_*`
- `DATABASE_URL`、`*_DSN`

刻意排除原 plan 的 `*_KEY` / `*_TOKEN` — 跟 API keys / OAuth tokens 重疊太多，亂自動產出會 silent break paired services。

**Decision rules**：
- 沒 missing required → `ok`
- 有 missing required + 任一在 deny list → `block`（user 必須手動設那些 paired credentials）
- 全部 missing required 都在 whitelist + `autoGenerateSecrets === true` → `auto-generated`
- `autoGenerateSecrets === false` → 全部走 `block`（首輪上線預設 OFF，operator 自己 opt-in）
- 混合（有 whitelist 也有 deny / unknown）→ `block` wins（user 修 unfix-able 的，下次再 auto-gen）

### Part 3：Settings toggle（R45 pattern）

`settings-service.ts` 加 `autoGenerateSecrets: boolean`，default `false`。`routes/settings.ts` schema + DEFAULTS 加同名欄位。沒做 web UI（要的話 PUT `/api/settings { autoGenerateSecrets: true }` 即可，R45 的 type-aware GET/PUT loop 已支援 boolean）。

### Part 4：兩個 enforcement 點

**Point A — pipeline-worker.ts Step 2.7**（Python only，新插在 Step 2 後 / Step 3 前）：

```typescript
if (detection.language === 'python') {
  const refs = extractPythonEnvVars(projectDir);
  const userKeys = parseEnvVarKeys(project.config?.envVars ?? '');
  const settings = await getRuntimeSettings();
  const verdict = decideEnvGate({ refs, userProvidedKeys: userKeys, autoGenerateSecrets: settings.autoGenerateSecrets });
  
  if (verdict.kind === 'block') {
    transitionProject(projectId, 'failed', { failedStep: 'Step 2.7: Required env vars', missingRequired, errorCode: 'env_vars_required' });
    return;  // short-circuit, 省 3-5 分鐘
  }
  if (verdict.kind === 'auto-generated') {
    UPDATE projects SET config = config || jsonb('{envVars: ..., autoGeneratedSecrets: [...]}');
  }
}
```

**Point B — deploy-worker.ts pre-build**（defense in depth）：LLM classifier 跑完之後、`buildAndPushImage` 之前再 check 一次。throw with `errorCode='env_vars_required'` 不要燒 Cloud Build minutes。

兩層 gate 的理由：Point A 早期擋住 99% 的 case（節省最多時間），Point B 防 LLM 把 env-detector 的 missing list 處理掉但實際上某些 var 還是必須（防護 LLM 過度樂觀）。

### Part 5：明確不做的事

- **不重寫 env-detector.ts** — 既有 80% 邏輯保留
- **不延伸到 Node.js** — env-detector 已經處理 Node patterns，且 Node 沒有 Python KeyError 那種 module-load 即崩潰的高頻 failure mode
- **不加 web UI 的 toggle** — API PUT 就夠了
- **不加密 auto-gen 的 secret** — 跟 codebase 其他 plaintext JSONB secret 一致（separate CSO concern）

## Consequences

**好處：**
- `luca-optimizer-kb` 那類 auto-gen 候選的 secret（`LUCA_JWT_SECRET`）若 operator 開 toggle → pipeline 自動產生 + 寫進 envVars + 繼續 deploy
- `POSTGRES_PASSWORD` / `DATABASE_URL` 等 paired credentials → block in Step 2.7（節省 3-5 分鐘 Cloud Run timeout），dashboard 顯示精確的 missing list，user 知道要設哪幾個
- `wavenet-ai-gateway-backend` 同樣模式，`erp-jwt-secret` 命中 `*JWT*SECRET*` whitelist
- 持久化 auto-gen value 到 `project.config.envVars` → 下次 deploy 同樣 secret，sessions 不會 invalidate
- 默認 `autoGenerateSecrets=false`，operator 必須 opt-in，避免「冷啟動就自動產 secret 給 prod」的意外
- 68 個 zero-dep 測試（29 extractor + 33 gate + 6 settings R49）鎖死所有 pattern

**代價：**
- Step 2.7 多一次 fs walk + 純函式分析（~50ms 級，vs 4 分鐘 timeout，明顯划算）
- 兩個 sibling 服務共用 `JWT_SECRET` 但分別 submit 時，會各自 auto-gen 不同值 → silent break。Mitigation：當 auto-gen 觸發時，未來可加「同 project_group 內若已有同名 var → 複製 value」邏輯（flag for follow-up，目前先用 deny list 的人工介入）
- Pydantic `model_config = SettingsConfigDict(env_prefix="APP_")` 沒處理 → 我們 extract `FOO` 但實際 expect `APP_FOO`。False-negative，gate 不擋 → Cloud Run timeout 還會發生（不比現況差）

**未來可能需要做：**
- Pydantic env_prefix / alias 支援
- Web UI toggle for `autoGenerateSecrets`
- Same project_group 內 secret 共享（避免 sibling 服務 silent break）
- 延伸 Node 端做類似 gate（目前 env-detector 涵蓋 Node 但沒 enforcement gate）
